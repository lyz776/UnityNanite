# Nanite portability and render-path contract

## Why this exists

The original runtime exposed independent Inspector switches. A serialized asset,
old ShaderCache, or a different graphics API could therefore select a path whose
kernels or resources were incomplete. Depth could still rasterize while visibility
IDs, indexed arguments, or hybrid queues were invalid.

The renderer now negotiates one path from runtime capabilities and imported kernel
contracts. Inspector fields are preferences when automatic negotiation is enabled;
they are no longer sufficient by themselves to enter a fast path.

## Negotiated paths

| Path | Required contract | Result |
|---|---|---|
| `Unsupported` | DX12, compute, base cull/compact kernels missing | Nanite GPU submission is stopped with a clear platform log |
| `HardwareCompat` | DX12 + base procedural-indirect contract | RGBA32F VBuffer and procedural indirect raster |
| `HardwareFast` | Compat + all camera/shadow packet kernels | Exact dynamic 32-bit triangle packets with procedural overflow tail |
| `Hybrid` | Fast + all classify/tile/software kernels | HW/SW is admitted by measured GPU cost; merge supports both compact integer and RGBA32F compatibility VBuffers |

HZB is an independent accelerator. It is used only when its kernel contract, scene
size admission, history validity, rejection benefit, and end-to-end GPU cost gates
all pass.

The large-scene path now uses the two-stage temporal contract expected by Nanite:
Pass 1 tests the selected cut against a stable previous-frame HZB and records every
rejection as a post-pass candidate; the depth/HZB generated by Pass 1 is then used by
Pass 2 to recover disocclusions. Previous HZB is admitted only when camera view-
projection, registry revision, geometry generation, and instance-transform generation
all match the frame that produced it. A camera/object/scene change disables temporal
occlusion for one frame, preventing the holes and flashing that caused the old path
to be disabled. Automatic path negotiation enables this contract even when the legacy
serialized `usePreviousHzbOnFirstCull` switch is off.

Compact `R32G32_UINT` is also independent. Startup draws known integer IDs into a
real integer render target and asynchronously reads them back. The ABI changes from
RGBA32F only after an exact round trip. Unsupported or broken drivers remain on
RGBA32F without depending on the renderer asset's serialized value.

The active decision is logged once as `[Nanite][Platform]`, including path, kernel
families, VBuffer ABI, compact-probe result, winding mode, and UAV ceiling.

## Winding contract

Procedural draws do not receive MeshRenderer's mirrored-transform correction.
Formal VBuffer, shadow procedural raster, camera packet queues, and shadow packet
queues now share one rule:

- positive transform determinant: preserve baked triangle order;
- negative transform determinant: exchange corners 1 and 2.

Formal and shadow raster currently retain `Cull Off` because imported source meshes
do not yet persist a bake-time front-face convention. The packet shader still applies
the determinant rule so a future per-mesh winding bit can safely restore back-face culling.

## Kernel and UAV contract

`Tools/Nanite/Validate DX12 Portability Contract` and the Windows build preprocessor
verify:

- Standalone Windows contains Direct3D 12 only;
- every Nanite compute source has `#pragma only_renderers d3d11` (Unity's DirectX
  HLSL backend for both DX11 and DX12);
- base, Indexed, shadow Indexed, and Hybrid kernels imported successfully;
- declared per-kernel writable-resource counts never exceed eight UAVs.

Runtime kernel discovery is per kernel family. One optional kernel failing import no
longer invalidates unrelated compatibility kernels, and no fast path is admitted
unless its complete family is present.

## Cross-machine acceptance

The portability gate is complete only when all of the following pass on an empty
`Library` and in a Standalone DX12 player:

1. zero C# or Nanite shader import errors;
2. zero `kernel invalid`, `resource is not set`, or `more uavs than maximum` errors;
3. 1, 16, 154, and 432 instances render with materials and four shadow cascades;
4. normal and mirrored instances have identical face visibility;
5. the platform log identifies the selected path and any fallback reason;
6. there is no synchronous GPU readback in a per-frame hot path;
7. HZB and Hybrid settle to enabled only when their measured total GPU time wins.

The Editor build guard makes items 1-2 fail before producing a player. Items 3-7
remain runtime/performance acceptance because they require the benchmark scene and
GPU timing.

For unattended dispatch validation, build `Tools/Nanite/Build DX12 Portability
Smoke Player` and launch it with `-force-d3d12 -nanite-portability-smoke`. The
switch keeps a hidden Player rendering in the background for 300 frames and then
exits; normal Player launches are unchanged.
# 2026-07-30 large-instance correctness and fixed-cost admission

- Automatic negotiation now stops at `HardwareFast`. Hybrid is only admitted by an explicit `HybridSoftwareHardware` request after its complete resource contract is available. This prevents the initial cost probe from dispatching a partially produced traversal-bin queue.
- The traversal-bin Hybrid shortcut is disabled until traversal produces the classify and tile resources as one contract. The complete post-cull classification path remains available for explicit Hybrid validation.
- Formal, indexed, shadow and software raster now use the same Unity source-mesh base winding flip XOR mirrored-transform rule. The earlier determinant-only rule corrected mirrored instances but left every regular generated draw in the opposite fixed-function front-face convention, which caused the large-instance fracture pattern.
- A scene-level low-submission admission path returns up to two fallback-capable instances, eight native submesh draws and 1.5M source triangles to URP. This removes Nanite's VBuffer/resolve fixed cost from the one-car case while dense instance scenes remain GPU-driven. Either Force flag retains explicit control when selected alone; selecting both is a conflict and falls back to automatic admission.
- Camera and shadow hardware raster no longer generate a transient fixed-function index stream. The GPU bit-packs `(triangleId, instanceId)` into one dynamic 32-bit packet and produces exact procedural DrawArgs. `SV_VertexID / 3` selects a packet and the three corners are decoded directly from resident page geometry. The instance field is sized from the active GPU Scene; the remaining high bits address triangles, with an automatic compatibility fallback if both domains exceed 32 bits. At the 432-car capture this halves packet bandwidth and raises the 128 MiB scratch capacity from 131,072 to 262,144 clusters, so all four cascades fit without a procedural tail.
- With HZB active, WriteDepth owns the initial Pass1 packets. Formal raster preserves that buffer and appends only Pass2 disocclusions from the tail of the same GPU visible queue; it never performs a second full packet rebuild when the queue remains within the shared capacity.
- Pass1 now writes the formal VBuffer together with its HZB depth. Formal consumes that preserved RenderGraph texture and rasterizes only the appended Pass2 recovery packets. This removes both the duplicate packet build and the duplicate Pass1 raster, while Resolve still executes once over the final VBuffer.
- `R32G32_UINT` remains guarded by the startup round-trip probe. When integer RT load/resolve fails, the production fallback is now `R32G32_SFLOAT`, encoding normalized `(instance+1, triangle+1)` IDs. The 32-bit packet address domain stays exactly decodable while VBuffer bandwidth drops from 16 to 8 bytes/pixel; `RGBA32F` remains the last-resort format.
- Runtime compute assets are owned by `Resources/NaniteRuntimeComputeResources.asset`. The RendererFeature still uses serialized references first, but repairs missing/stale Player references from this bundle. The build guard rejects an incomplete bundle, preventing successful builds that negotiate to `Unsupported` only after launch.
- HZB tests use a conservative perspective sphere rectangle, real mip dimensions, integer texel loads, and refuse occlusion when the stopped pyramid cannot cover the rectangle with at most 2x2 texels. This follows the conservative occlusion invariant used by production GPU-driven renderers: false visibility is acceptable; false occlusion is not.
- The same packet ABI is used by all four shadow cascades. Sequential native-atlas recording reuses the full scratch allocation; batched recording stores an explicit packet base per cascade and never depends on `startVertex` semantics.
- Packet scratch and both indirect-argument buffers are explicit RenderGraph resources. Multi-chunk frames therefore have a real `build N -> raster N -> overwrite N+1` dependency instead of relying on command-recording order or global-state side effects.
- Raster diagnostics are slice-aware: expected vertices are summed only over the cluster chunk represented by the current DrawArgs, rather than comparing one chunk with the complete visible queue.
- Previous-frame HZB is admitted on FirstCull only while view-projection, registry, geometry and transform generations are identical; current-frame HZB re-tests every rejection in SecondCull. Formal and shadow raster remain double-sided until a bake-time winding convention is stored per mesh.
- A clean-Library DX12 Development build and 300-frame Player run completed with `HardwareFast`, all base/indexed/hybrid/HZB kernel contracts present, packed page streaming resident at 60/60, four cascades, `[Pass1VBuffer]` and `[PacketReuse]`, and zero invalid kernels, missing resources or UAV overflows. The tested machine rejected `R32G32_UINT` and correctly selected `RG32F/normalized32`.
